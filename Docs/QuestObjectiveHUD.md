# クエスト目標トラッキングUI

## 構成と設計
既存の MissionManager2D / MissionDefinition2D / MissionHUD2D / MissionMenuUI を拡張。独立したクエスト管理や報酬処理は追加しない。
目標の判定は GameSessionManager の保存済み StoryFlags を参照する。受注状態と追跡対象は既存のミッション保存を使用する。UI自身は進行フラグ、アイテム、報酬を変更しない。

全12クエスト（メイン4件・サブ8件）に適用済み。S1S01「毒に倒れたフィン」の搬送先はバルド。
1. 旧居住区でフィンを捜し、治療を申し出る：会話末尾の了承選択（会話を開くだけでは未達成）。
2. 救急キットの解毒剤で治療する：既存の治療成功イベント。
3. フィンをバルドのもとへ運ぶ：既存の担ぎ操作と搬送判定。
4. バルドに報告して報酬を受け取る：既存の報告会話。
搬送でネイティブミッションは達成するが、報告が残っていれば引き続き追跡できる。報告後に別の追跡可能なミッションへ切り替わる。

## UI
StoryIntegration/QuestTrackingHUD の下に Panel/Current（クエスト名・次の目標）と Panel/Completion（完了通知）を配置する構成。
右上の半透明パネル、基準解像度1920×1080、CanvasScaler、セーフエリア対応。本文と完了通知は文字量に応じて高さを計算し、省略せず折り返す。本文の画面上の文字サイズは最低16pxを目安に維持。クリックを遮らない。町では施設ボタンとの重なりを避けた右寄りの空き位置に配置。
目標変更は約0.3秒のフェード、完了通知は約2.5秒保持してフェードアウト。複数の達成通知は順に表示。
既存ミッションメニュー（通常Mキー）で選択して「追跡する」。詳細欄には現在の目標と全目標の達成状態を表示。

## Editor設定と他クエストへの適用
MissionDefinition2D の Display Objectives に目標を順番に設定する。
- id：安定した識別名。text：日本語の表示文。
- anyOfFlags：いずれかが成立する条件。
- allOfFlags：すべて成立する条件。両方を指定した場合は両方を満たす必要がある。
- Objective Finish Flag：報告も含めた最終完了フラグ。成立時は全目標を達成済みとして表示。
フラグ名は完全名（例 story/S1S01_Treated）。未設定の条件は未達成。既存の入手・調査・救出・帰還処理が成功した時に保存フラグを立てることで同じ仕組みを使用できる。会話の表示だけで達成させない。
達成フラグは原則一度立てたら維持する。所持数の増減など可逆条件をそのまま達成フラグとして使うと、再成立時に通知される。
受注前・順不同でも保存フラグから計算し、追跡切替・ロード直後には過去の完了演出を再生しない。未追跡クエストの進行は従来どおり継続する。
目標を設定しない既存クエストは従来の説明と数値進捗を表示する。今回の本編12件はすべて設定済み。新規クエストもこのデータで追加できる。

任意の効果音は QuestTrackingHUD の MissionHUD2D > Objective Completed Sound に AudioClip を設定する。未設定は無音。保持秒数・フェード・音量もInspectorで変更可能。
生成データを継続運用する場合は StoryIntegrationBuilder.Objectives.cs の定義も更新する（データ再生成でInspector変更を上書きするため）。既存HUDオブジェクトは再生成時に維持する。

## 確認手順
Town_Mainから受注してstage1へ移動し、Mメニューでフィンを追跡する。
会話を保留した時は最初の目標が残ること、了承で治療目標になることを確認。
Tキーの既存操作で解毒剤を使用し、次がバルドへの搬送になることを確認。
既存の担ぎ操作でバルドへ運び、報告目標が残ることを確認。この状態で保存・ロードして追跡と目標が復元され、通知が再生されないことを確認。
報告後に100Gが一度だけ入り、報告完了・クエスト完了通知が出ることを確認。
別クエストを追跡している間も治療などを進め、フィンへ切り替えた時に最新状態が表示されることを確認。
1280×720、1920×1080、横長画面で文字と既存HUDの重なりを確認する。

自動テストは StoryIntegrationBuilder.ReconcileAndRunTests。既存の12クエスト・保存・救出テストに、目標更新・通知重複・搬送後の追跡保存を追加。実行結果は今回の作業報告を参照。手動操作による見やすさの確認とは区別する。

## 本編全クエストへの適用（2026-10-20追記）
| クエスト | 表示する目標の流れ |
|---|---|
| 消えた遠征隊の足跡 | ステージ1の図書室で日誌調査 → 町長へ報告 |
| 封鎖された昇降路 | ステージ2の機械室で記録箱調査 → 町長へ報告 |
| 失われた巡礼路 | ステージ3の経路図調査 → 町長へ報告 |
| 消えた貴族 | ステージ4の庭で町のことを伝える → 結末を選択（保留・再訪可） |
| 毒に倒れたフィン | 捜索・了承 → 治療 → バルドへ搬送 → 報告（前回実装を維持） |
| 古城の設計図 | ステージ1の資料室で設計図回収 → 同ステージのグレンへ渡す |
| 奪われた補給物資 | ステージ2で補給箱または代替物資を回収 → 同ステージのロアンへ渡す |
| 新たな稼ぎ口 | 搬入記録調査 → フィン救助の報告済みを確認 → 町長と入町許可交渉 → ステージ2のバルドへ報告 |
| 止まった水路 | 軸受け・弁・歯車を回収 → ステージ2のグレンへ部品を渡す → 水門で復旧 → 同ステージのグレンへ報告 |
| 争いの終わる場所 | 裏方用通路調査 → ステージ3のロアンへ提案 → 同ステージのバルドと停戦交渉 → ロアンへ報告 |
| 失われた交易路 | 交易路調査 → 「新たな稼ぎ口」完了 → ステージ3のバルドへ報告 |
| 眠れる古城 | 修繕台帳・回廊調査 → ステージ2の水路復旧 → ステージ3のグレンへ報告 |

すでに成立した目標は飛ばして最初の未達成目標を表示する。部品や調査の表示順は案内の優先順であり、攻略順を制限しない。代替物資も既存の S2S01_Goods を使うため、本来の補給箱の回収を追加要求しない。
「眠れる古城」は S2S03_WaterRestored が必要であり、水路クエストの最終報告までは要求しない。結末Cの三派閥支援は任意の分岐条件なので、全プレイヤーへの必須目標にはしない。
回収フラグは品物を失っても残るため、引き渡し目標には所持品へ入れることと紛失時の再取得を案内する。新しいフラグやセーブ項目、報酬処理は追加していない。

今回の変更は StoryIntegrationBuilder.Objectives.cs、StoryIntegrationTests.cs、Mission_S1M01 / S1S03 / S2M01 / S2S01 / S2S02 / S2S03 / S3M01 / S3S01 / S3S02 / S3S03 / S4M01 の11個のasset、および本書。シーンと会話を再生成しない専用入口 UpdateAllObjectivesAndRunTests を使用。

## HUDの見た目・解像度対応（2026-10-20）
変更: MissionHUDSafeArea2D.cs、MissionHUD2D.cs、検証用 QuestHUDVisualTests.cs。
- 固定高さ＋省略表示から、TextMeshProの推奨サイズを使った可変高さに変更。短文では小さく、長文では本文・完了通知を個別に拡張する。
- 本文・通知は最低16px、タイトルは最低17pxを目安にして、低解像度での過度な縮小を避ける。
- 町の入れ子Canvasを親いっぱいに伸ばし、画面外や極端に小さい領域へ配置される問題を修正。
- 町では表示中のボタン領域に余白を付けて回避し、画面の右寄り上部に入る位置を選ぶ。ダンジョンは右上を維持。
- 背景の不透明度を上げ、明るい町背景でも文字を読みやすくする。
- 会話・ミッション一覧・インベントリ・取引など既存画面が開いている間はHUDを一時非表示。完了通知のタイマーを止め、閉じた後に表示を再開する。

Unityの実際のGameビューの描画済みテクスチャを取得して確認。シーンやユーザーのセーブファイルは変更しない。
検証解像度: 1280×720 / 1920×1080 / 2560×1440 / 2560×1080 / 1024×768。
Town_Mainとstage1で、全クエストの本文・通知について文字のはみ出し、HUDの画面境界、表示中のボタンとの交差を自動検査。代表画像も目視確認。町の会話とMメニューでの非表示・復帰を実行確認。
結果: Logs/QuestHUDVisual.log の QUEST HUD VISUAL PASS。画像は Logs/QuestHUD/ 配下。
任意の解像度で完全に保証するものではなく、上記5解像度で検証済み。その他の取引画面などの開閉判定は既存IsOpenを参照する実装で、個別操作の全組合せは未検証。

既存UI側の残課題: 1024×768などでは、町施設ボタンやミッション一覧自体に画面外へ出る箇所がある。今回のHUDは重ならないように調整したが、施設・一覧全体のレイアウト改修は行っていない。
Editorで追加設定は不要。既存のMissionHUDSafeArea2Dが起動時に適用するため、シーンの再生成も不要。
